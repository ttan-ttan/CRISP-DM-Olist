1. Silver Cleansing & Standardization Complete

Once all 9 datasets were cleansed using the standardized PySpark template, the entire team transitioned together to the Gold layer.

2. Gold Business Logic Alignment & Team Raising

We pre-defined join sequences and aggregation formulas together. Whenever schema mismatches, null edge cases, or pipeline improvements arose, they were raised and discussed with the team to agree on a consensus before updating the code.

3. Power BI DAX Validation & Presentation Deck

We connected Gold Delta tables directly to Power BI via Direct Lake mode. We checked and validated DAX measures against expected business results before finalizing presentation slides.

PROS (Real Project Examples)
  • Zero Pipeline Crashes: Enforcing explicit schema readers prevented null crashing on 100k+ Olist order records.
  • No Waiting Deadlocks: Teammates working on sellers or payments didn't have to wait for the geolocation dataset to finish.
  • Asynchronous Progress: Allowed team members to learn PySpark at their own pace without delaying core pipeline testing.
CONS (Real Project Challenges)
  • Upfront Workload: Required extra hours of study from me to build and document the initial prototype.
  • Fabric Trial API Limits: Encountered Microsoft Fabric trial tenant locks, forcing us to pivot to GitHub Actions + Power Automate webhooks.
  • Git Merge Conflicts: Required careful Git branch management when merging team notebook updates.

Case Study Narrative

1. Facing the Problem: Waiting & Confusion

Initially, our project hit a bottleneck because we worked in a linear way. One person was waiting for another to finish before they could start their part.

With 4 different learning speeds, some teammates felt lost and didn't know what to do next. Enforcing rigid deadlines only caused frustration and stress.

Core Data Engineering Insight

"Linear dependencies stop team momentum. Tasks must be decoupled so everyone can progress asynchronously."
